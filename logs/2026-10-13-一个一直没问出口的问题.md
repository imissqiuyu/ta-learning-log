### ① 护盾看起来是"一张网"，不是六边形

- **现象**：球面上是一层很密的网格，看不出六边形
- **根因（AI 的参数错）**：`HexScale = 6.00` 的含义是「每**局部单位**几个六边形」。
  基础球体的局部坐标是 **±50** → 直径上挤了约 **600 个六边形** → **摩尔纹**。

  改成 `fwidth(edge)`（屏幕空间导数），跟密度解耦。
- **谁的问题**：**AI**

> 💡 这里有个很漂亮的对照：`fwidth` 就是 `ddx/ddy` 那一族 —— 正是**坑 1**里的函数。
> 坑 1 说「不能用 DDX」是指拿它求**法线**（语义错），
> 拿它做**抗锯齿**是标准做法。**同一个函数，用对地方就是对的。**

  所以任何进度下都是碎洞。真实游戏里的溶解都会再叠一个方向梯度。
- **修复**：新增 `SweepBias` / `SweepHeight` 两个参数，
  `mask = noise×(1-bias) + 高度×bias − Progress`
  → 进度推进时，分界线像一条线扫过物体，噪声只负责让线变毛。
- **谁的问题**：**AI**（不是 bug，是设计不到位）

- **谁的问题**：**AI**（选了一个带"无法验证的前提"的方案）

> 注释与实现不符是最难查的 bug —— 它让读代码的人（包括写它的 AI）
> 以为那段是对的。**

### ② 颜色被高度线性驱动，而且色差 50 倍

```
depth = saturate(H0 * 0.5556 + 0.5)     ← 高度几乎直线映射成颜色
Deep(0.012) → Shallow(0.62)             ← 差 50 倍
```

高度的等值线于是**直接变成可见的硬色阶**。
①的菱形格 + ②的硬色阶 = 我看到的瓷砖。

### ③ 光照方向是反的，漫反射那一项完全是死的

```python
light = vector("LightDir", (0.4, 0.7, -0.6, 1.0))   # Z 是负的 = 光从下往上照
```

水面法线朝上 → `dot(N, L) ≈ -0.63` → `saturate` 之后**恒等于 0**。
所以浪怎么起伏，明暗都不变。

### 修复

| | 改前 | 改后 |
|---|---|---|
| 高度场 | 只有 3 个正弦 | 3 个正弦 **+ 真正的噪声** |
| 颜色耦合 | `H0 × 0.5556` | `H0 × 0.20` |
| 色差 | 50 倍 | 约 4~5 倍 |
| 光照方向 | `Z = -0.6` | `Z = +0.76` |

**谁的问题**：三个都是 **AI** 的。
（注释是它写的、代码是它写的、光照参数也是它填的 —— 而且这三处互相掩护，
任何一个单独存在都不致命。）

### 技术层面

| 学到 | 说明 |
|---|---|
| **规则格子 = 周期函数的等值线** | 一眼"像瓷砖"，可以直接定位到"高度场缺噪声" |
| **硬边色阶 = 线性映射 + 大跨度** | 颜色被某个量线性驱动、且色差几十倍，就会画成等高线 |
| **明暗不变 = 点积恒为常数** | `LightDir` 的 Z 写反了，`saturate(dot(N,L))` 恒为 0 |

## ⚠️ AI 犯的错（这条要记清楚）

它的思路是"我改了几行代码" —— 但**正确的影响范围要按「数据依赖」算**：

```

    → 关卡里对旧资产的引用全部失效
```

**它漏掉了中间那一环。** 结果我白跑一趟，还看到一个像"全部失败"的画面。
