### B 类 · UE 材质系统（8 个，**全是 AI 的错**）

#### B1 · 三个 UE 事实凭记忆写错了

| 错误写法 | 正确写法 |
|---|---|
| 用 `Fmod` 求小数部分 | `Fmod` 是**截断**语义，求小数要用 `Frac` |
| Additive 有 Opacity 项 | **叠加公式里没有透明度项**，也不兼容动态光照 |
| 用 `LocalPosition` 材质函数 | 5.5 之后**已废弃**，要用 `LocalPosition` 节点 |

**教训**：**凭记忆写引擎细节 = 必然出错。** 要去查官方文档或源码。

#### B2 · 材质函数和材质是【两套 API】

| | |
|---|---|
| **现象** | `NativizeProperty: Cannot nativize 'MaterialFunction' as 'Material'` |
| **根因** | 建节点/排版/更新，材质和材质函数**各有各的函数** |
| **解决** | 加 `is_function(host)` 判断，分派到对应 API |
| **谁的问题** | **AI** |

#### B3 · 函数输入节点：默认名字 `In`、默认类型 `Vector3`

| 字段 | 默认值 | 坑 |
|---|---|---|
| `InputName` | **`In`** | 拖两个节点进来**都叫 In** → 重名报错 |
| `InputType` | **`Vector3`** | 你以为在传标量，其实是三分量向量 |

**我在 UE 里亲手遇到的报错**：**「函数输入命名必须独一无二」**

排查后发现：引擎源码里改名字时会拿新名字和图里**其他所有函数输入节点**比对，
重名就弹窗**并把名字回滚**。

**解决**：每个函数输入节点都显式设 `input_name` + `input_type`。

#### B4 · `bUsePreviewValueAsDefault` 不开 → Missing function input

| | |
|---|---|
| **现象** | `(Function MF_TA_Dissolve) Missing function input 'EdgeWidth'` |
| **根因** | 调用方没连这个输入时，引擎要退回用 Preview Value；这个开关**默认是关的** |
| **解决** | 建节点时显式打开 `use_preview_value_as_default` |
| **谁的问题** | **AI** |

> 💡 **顺带学到**：C++ 里叫 `bUsePreviewValueAsDefault`，
> 但 **UE 的 Python 命名会去掉布尔属性开头的 `b`**。
> 这是从 `bUseCustomPrimitiveData` → `use_custom_primitive_data` 反推出来的。

#### B5 · 函数输入没连线 → 预览值默认 **0** → 水面全平

| | |
|---|---|
| **现象** | 水面**完全没有波浪**，而且 `Relief` 参数**怎么调都没反应** |
| **根因** | `MF_TA_WaterHeight` 的 `Amplitude` 输入**没连线** → 退回 Preview Value → 默认 **0** → 高度场恒等于 0 |
| **解决** | 显式连一个常量 1.0；同时给预览值设有意义的默认 |
| **谁的问题** | **AI** |

> 🎯 **这个坑最有价值的地方是它的「不可见性」：**
> **编译通过、零警告、资产保存成功 —— 只是结果是错的。**

#### B6 · FunctionOutput 的输入引脚「没有名字」

| | |
|---|---|
| **现象** | Python 连线到函数输出节点，传 `"A"` 永远失败 |
| **根因** | 源码 `MaterialExpressionFunctionOutput.h` 里 `GetInputName()` 直接 `return NAME_None` |
| **解决** | **传空字符串**（源码里写了「空名字 = 第 0 个输入」） |
| **谁的问题** | **AI**（但这是引擎的设计，只能查源码才知道） |

#### B7 · 输入引脚名会被「缩写」

| | |
|---|---|
| **现象** | 连线到贴图 UV，传 `"Coordinates"` 永远失败 |
| **根因** | `MaterialGraphNode.cpp` 的 `GetShortenPinName()` 会**先把名字缩写再比对** |
| **解决** | 传缩写名 |

| 属性名 | 连线要传 |
|---|---|
| `Coordinates` | **`UVs`** |
| `TextureObject` | **`Tex`** |
| `Exponent` | **`Exp`** |
| `MipLevel` / `MipBias` | `Level` / `Bias` |
| `Input` | `""` |

#### B8 · float3 → float2 不自动转换

| | |
|---|---|
| **现象** | `Cannot cast from larger type float3 to smaller type float2` |
| **根因** | `Position` 是三分量，贴图 UV 是两分量；**降维转换 UE 拒绝自动做** |
| **解决** | 中间插一个**组件遮罩**，明确取 XY |
| **谁的问题** | **AI** |

> 💡 这个设计其实是对的：**信息丢失必须由人决定，不能让编译器猜。**

### C 类 · 渲染原理（2 个，**AI 的错，而且是最严重的**）

#### C1 · 用 DDX/DDY 求水面法线 ⭐

| | |
|---|---|
| **现象** | ① 从高处看有**规则矩阵排列的黑点** ② **波浪完全没有起伏**，怎么调参数都没用 |
| **根因** | **DDX/DDY 是屏幕空间导数**，不是世界空间 |
| **解决** | 改成世界空间**有限差分**（抽 `MF_TA_WaterHeight` 调用 3 次） |
| **谁的问题** | **AI**（而且 AI 自己在代码注释里写了「这是错的，只是先让它跑通」） |

**两个症状分别对应什么：**

```
规则黑点  ← GPU 按 2×2 像素块（quad）算导数，块本身是规则网格，
            高频高度场在块边界跳变 → 规则暗点

没有起伏  ← 导数量级只跟屏幕缩放有关，跟波浪真实陡峭度无关
            → 法线恒等于 (0,0,1) → 怎么调振幅都没用
```

> 🎯 **「怎么调参数都没用」是这类 bug 的典型特征** ——
> 说明那个值压根没进到计算里。

#### C2 · 护盾材质是个灰球 —— `line` 是 HLSL 保留字 ⭐

| | |
|---|---|
| **现象** | 护盾材质**编译失败**，UE 用默认材质顶替 = 灰球 |
| **报错** | `error: modifiers must appear before type` |
| **根因** | 我用了 `float line = ...`，而 **`line` 是 HLSL 图元类型关键字** |
| **解决** | 改名成 `hexLine` |
| **谁的问题** | **AI** |

> ⚠️ **这个报错最难的地方：它完全不提「保留字」。**
> 报错行语法明明是对的。
>
> **做完之后我写了个脚本，把所有 Custom 节点的变量名全部对照 HLSL 保留字表扫了一遍** ——
> 确认只有这一处。

#### D2 · 删除资产顺序反了 → 误导性报错

| | |
|---|---|
| **现象** | 日志里出现 `Failed to compile ... Missing Material Function`，但最终结果是对的 |

## 💡 今天学到什么

### 技术层面

1. **屏幕空间导数不能用来求几何量** —— DDX 求的是「这个像素和邻居差多少」，不是「这个表面有多陡」
2. **混合模式的代价差别很大**：不透明 1×、已遮罩 1.5~2×、半透明 3~10×
3. **Masked 的成本不在"混合"，在 Early-Z 失效**（discard 让硬件没法提前剔除像素）
4. **叠加不用排序**（加法交换律）—— 这才是它在游戏里这么常用的真正原因
5. **有限差分求法线**：采三个点做差商，通用、可维护，代价是算 3 遍

### 方法论层面（**更重要**）

今天最值钱的收获不是任何技术点，而是这四个**验证习惯**：

| 习惯 | 来源 |
|---|---|
| **不要相信「日志说成功」** | D1 资产没保存 |
| **不要相信「编译通过」** | B5 函数输入没连线、C1 DDX 法线 |
| **API 行为诡异 → 去读源码，别猜** | B6/B7/B2 |
| **报错出现的位置 ≠ 问题所在的位置** | D2 删除顺序 |
