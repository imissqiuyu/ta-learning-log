## 今天做了什么

1. AI 先探测环境：20 线程、ffmpeg(libx264/aac)、numpy/PIL、中文字体（`simhei.ttf` 能用，`msyhbd.ttc` 带 index 参数会报错）
2. 写了 `audio.py`：120 BPM / A 小调 / 30 秒，鼓、贝斯、铺底 Pad、琶音、Riser、混响全部用正弦波+噪声+FFT 滤波合成
3. 写了 `render.py`：五段镜头 + 交叉溶解 + 冲击白闪 + filmic 调色 + bloom + 颗粒 + 中文排版
   - 0-6s 光速隧道（极坐标 + 分形噪声）
   - 6-14s 液态金属（三层 domain warping + 假法线高光）
   - 14-20s 1.4 万颗粒子在 curl noise 流场里积分轨迹
   - 20-26s 铬球（解析法球面求交 + 反射方向采样程序化影棚）
   - 26-30s 球退远压暗 + 标题
4. 12 进程并行渲染 900 帧（约 25 分钟），无损分段 FFV1 → concat → x264 CRF17 → 混 AAC
5. 出 4 张封面、发布文案、制作说明、10 张静帧

成片校验：30.00 秒整 / 1080×1920 / 30fps / H.264 12Mbps / AAC 192k / 峰值 -0.9dB。

## 卡住的地方

### 1. 多进程直接崩：`PermissionError [WinError 5] 拒绝访问`

- **现象**：`multiprocessing.Pool` 一创建就抛 PermissionError，报在 `_setup_queues` → `Pipe()`
- **根因**：Windows 上 Pool 靠命名管道通信，这台机器的沙箱不允许程序开命名管道
- **解决**：不修它，换架构 —— 12 个**独立进程**各渲 75 帧，各自 pipe 给自己的 ffmpeg 输出 FFV1 无损分段，最后 concat 拼起来
- **谁的问题**：**环境**。AI 没有硬碰限制，改架构比改限制快

### 2. ffmpeg 拼接报 "No such file or directory"

- **现象**：`-f concat -i frames/concat.txt` 明明文件在，ffmpeg 说找不到
- **根因**：工作目录是中文路径 `E:\抖音作品`，相对路径 + 中文 CWD 下 ffmpeg 读不到
- **解决**：全部传绝对路径，并改用 `concat` 滤镜（多个 `-i` + `filter_complex concat=n=12`），彻底不依赖 list 文件
- **谁的问题**：**AI 的**。一开始没考虑中文路径

### 3. 铬球整颗消失（AI 的错，最耗时间的一个）

- **现象**：铬球那段渲染出来只有地面上的一个黑椭圆形阴影和一条亮弧，球本身一个像素都没有。第一眼我以为"球跑到画面下方去了"
- **根因**：光线与球求交的近根符号写反了。正确是 `t = b - sqrt(b²-c)`，AI 写成了 `t = -b - sqrt(...)`，于是所有交点 `t < 0` 全被剔除
- **怎么定位的**：**让 AI 打印命中像素数**，输出 `hit pixels 0 of 2073600` —— 一行数字就直接否定了"球位置不对"的猜测，确定是求交本身失效
- **谁的问题**：**AI 的**。而且这类错误不报错、不崩溃，只是画面空了，最容易被误判成"构图问题"

### 4. 修好求交后，球变成一颗"珍珠"（AI 的第二个错）

- **现象**：球出现了，但上下都被糊上一层均匀的灰蓝，像磨砂珍珠，完全没有金属感
- **根因**：菲涅尔写反了。正确 `F = (1 - n·v)³`，写成了 `(1 + n·v)³`，球心区域直接取到 1，整体加了一层平光
- **还发现第三个问题**：影棚环境太暗太散，铬球反射不到具体的东西 —— 球好不好看取决于**环境有没有结构**，不是球本身
- **解决**：菲涅尔改正；环境重做成"矩形柔光箱 ×3 + 顶部灯管横带在半圈方位上衰减 + 压暗地面"，曝光降一档
- **谁的问题**：**AI 的**，两个都自己复盘抓出来的

### 5. 13 个中文字被横向裁掉

- **现象**：「零素材 · 零模型 · 纯代码」两头都被切了
- **根因**：字号 86 × 13 字 ≈ 1160px > 1080px 画布，排版没有自动缩放
- **解决**：`text_block()` 里加自适应循环，超宽就按比例缩字号；同时加了一层柔光遮罩，保证压在液态金属那种花背景上文字也压得住
- **谁的问题**：**AI 的**，属于没做边界检查

## 学到什么

### 技术层面

1. **铬球 = 环境，不是球。** 金属反射没有自己的"颜色"，全是环境的形状。想让球好看，就得先把环境造出结构（柔光箱的边、灯管的横带、地面的暗）。这一点搬到 UE 里完全一样：反射球看不出材质，只能看出 HDRI。
2. **菲涅尔和光线求交是"错了不报错"的经典。** 符号反了程序照样跑完 900 帧，只是画面变难看。所以这类代码要靠**数值断言**（命中像素数为 0 就该报警），不能靠肉眼看结果。
3. **domain warping（噪声拿噪声当 UV 再采样）就是液态金属那套做法。** UE 材质里能一模一样地复刻：两个 Noise 节点互相喂 UV、再叠一层、用位移当法线。这条片子的效果可以直接当材质练习的参考图。
4. **curl noise（对噪声势函数取旋度）能得到无散流场**，粒子进去就自己排队走成丝，不需要手 K。UE 里 Niagara 用 Curl Noise Force 就是同一个东西。

### 方法论层面

1. **画面不对的时候，先要数字，别继续看画面。** 打印 `hit pixels` 一个数就定位了求交 bug；只看图会一直往"构图/位置/相机"的死胡同里钻。
2. **环境限制不要硬碰。** 多进程被禁 → 直接换"多进程组"，不改规则、不申诉，一次就通。
3. **给 AI 目标，别给方案。** 我只说了"要成品发抖音"，它自己拆成音轨/渲染/封面/文案/校验五件事，还自己发现编码器和沙箱限制。要是我先规定"用 PR 剪"，后面全废。
4. **中间产物要留一条退路。** 无损分段 FFV1 留着，改一行字幕重渲一段再拼就行，不用从头跑 25 分钟。
